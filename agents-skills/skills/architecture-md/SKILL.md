# architecture-md

## What this skill owns

**Read `references/architecture-md-format.md` before any format work, rather than reconstructing the format from memory.** Its Contents line names every section it covers.

**Keep this skill the only home of the format.** A second home drifts from the first, and nothing tells a reader which of the two they are holding.

`architect` designs, roasts, maintains and validates the contract; this skill owns the format each of those procedures reads, and any other doc or brief reaches that format through this skill.

## How another skill or brief reaches the format

**Reference this skill by name with the section number kept - `architecture-md` §4 - and never by pasting the file's text into the referencing doc.** A name resolves to this skill wherever it is installed, while a pasted body drifts as the stale instance.

**Inline into a brief only a formula or a glob shape, never a body of rules.** That bound keeps a needed fragment from legalising the drift the single-home rule above prevents.

**Mark as secondhand any fragment of the format a brief restates, at the point of restating.** A brief handed no skill directory cannot reach the file, so its wording is all the reader gets, and an unmarked fragment passes for the rule itself.
