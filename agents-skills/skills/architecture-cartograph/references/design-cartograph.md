# Procedure 1, cartograph - the tree states a decision already made

The user's architecture is decided and the tree already implements it; this mode writes that decision into the format. The steps below run above the four steps `architect` shares across all three modes.

**Read `architecture-md` §4 before asking the first question below.** It is the section this mode strains: §4 bans documenting the tree, and every step here exists to keep transcription on the legal side of that ban.

## Whether this is a transcription at all

**Ask what each layer is for before opening the tree.** A decided architecture can be stated from memory, and the answer owes the responsibility plus the distinction the split protects - an answer that needs the folders open is read off them.

**Say the mode has no input the moment a layer can only be named by its folder, at any asking.** That user is discovering, not recalling, and cartograph gives the tree no vote on the decomposition, so it would emit an inventory.

**Put design democrat to the user rather than switching to it yourself.** The mode is the user's call, and switching without them leaves the repo's record naming a mode nobody is running.

## Where the decomposition comes from

**Write the layer set, each responsibility and each rationale down from the user's answers before the tree is opened.** They are what the tree gets compared against later, and an answer recovered after the tree is in context is contaminated by it.

**Take the user's statement first even where the tree is already in context, and say what you have already read.** Whatever is read first becomes the template, so an unannounced look lets your reading pass as the user's decision.

**Let the tree supply the `Paths` cell and the globs, and nothing else.** The user's statement says what the layers are; the tree says only where the code implementing them currently sits, which is the one fact the user cannot recite.

**Write each glob for the intended home, per `architecture-md` §1, even where today's files sit somewhere narrower.** Mode C reads the tree for paths and is still not licensed to hand-list the files that happen to exist.

**Take the forbidden edges from the shared coverage step, never from the imports.** The user deciding the layers is not the user deciding the edges, and an edge set read off the import graph launders every pair the code happens to cross.

## Whether a disagreement is drift or a wrong statement

Disagreement between the statement and the tree is the expected output here, not the exception. Telling the two kinds apart is this mode's real work.

**Put a disagreement to the user as where the code belongs, never as why it is there.** Asking why invites a defence of the placement, which is §4's laundering with the user holding the pen; asking where makes them rule from what they stated.

**Read the user's move as the answer.** Moving the file leaves the stated rule intact, and the disagreement is drift; moving the rule to fit the file is §4's widening of a layer's definition, and the responsibility came off a folder.

| The tree disagrees | What it is evidence of | What this mode does with it |
|---|---|---|
| a file or a handful sit outside the layer their stated responsibility gives them | drift: the contract holds and the code moved | writes the contract as stated; the stray becomes a procedure 4 finding |
| a layer's occupants contradict its stated responsibility as a body | that responsibility never governed, so the statement was aspiration | nothing yet: the layer goes back to the user unresolved |

**Put a layer back to the user rather than reconciling a wrong statement yourself.** The decomposition is the user's in this mode, so reconciling it for them is design under a transcription brief - the way a cartograph run ends as an inventory.

**Keep a stated layer the tree does not yet implement.** The decision preceding its code is the normal direction here, and dropping the layer because nothing fills it deletes a decision on the grounds that the code has not caught up.

## What the match to today's code does not license

**Write the file as a prescription, exactly as the other two modes do.** That the code currently matches it is a fact about today; this mode differs from the other two in where the decomposition came from and in nothing downstream of that.

**Never re-derive the file from the code after it is written.** A later divergence is procedure 4's finding, and a file re-read off the tree whenever the tree moves is a description that can never report drift because it has none.

**Refuse every one of §4's laundering moves in this mode too.** This mode's licence is that the user decided the shape, never that the code may set a rule - and those moves are how a transcription becomes a description without a word of it changing.

## Where this mode hands off

**Say at handoff which stated layers the tree does not yet implement.** This mode keeps a layer the user stated and the tree has not built, so the first audit surfaces those as unrealised pairs - absence where the edge was allowed, silence where it was forbidden - with nothing recording that they were intended.

**Work `architect`'s four shared steps once every layer has a statement reconciled against the tree.** §2's coverage questions are all still open there - a decomposition says what the layers are and nothing about threading, failure or data ownership.
